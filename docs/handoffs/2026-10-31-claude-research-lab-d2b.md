## 1. 定位与切片

Research Lab 是独立的能力域（`/research`），与 Showcase 项目双向关联。它回答的问题是“这条结论凭什么成立”：每条研究声明都能追到证据，每个实验记录都写明方法、环境、版本与可复现方式，并如实给出状态。

切片的选择依据 `2026-10-31-claude-showcase-d2a.md` 第 6 节的 R0–R3 规划：

| 阶段 | 本次 |
| --- | --- |
| R0 声明账本 | 完成。声明 → 证据 → 实验的账本，按证据等级筛选，可直达单条声明 |
| R1 证据查看 | 部分。源码、测试与站内文档可直接打开；证据资产（CSV、权重、图片）仍等 L-1、L-2，页面标注“尚未开放分发” |
| R2 复现运行 | 浏览器内子集。确定性实验可在访客设备上用同一份代码重算，并与参考结果按协议容差逐项比对。不持久化、不经过服务端，因此不依赖 L-3、L-4 |
| R3 第三方实验室 | 未涉及（L-5） |

D2-A 交接中留给 Owner 的三个问题，本轮任务说明已经决定两个：Research Lab 是独立产品区域；公开访问者不能触发服务端复现。计算预算与配额仍待决定，需求写在第 8 节。

## 3. 数据与真实性边界

**Fixture 内容**：

| 研究项目 | 来源 | 实验 |
| --- | --- | --- |
| 路线优化求解器 | 真实项目 | ROUTE-01 可本地复现 · ROUTE-02 可本地复现 · ROUTE-03 测试覆盖 · ROUTE-04 计划中 |
| 神经网络训练场 | 真实项目 | NN-01 可本地复现 · NN-02 测试覆盖 · NN-03 计划中 |
| 排序算法对照实验 | 示例项目（计算真实） | SORT-01 可本地复现 · SORT-02 受阻 |
| 体数据三维重建 | 示例项目 | VOL-01 受阻 · VOL-02 受阻 |

**没有手写任何结果**。可本地复现的实验在 Fixture 里只写了实验程序的名字；参考结果在页面渲染时（静态生成，即 `next build` 期间）运行仓库代码得到，访客在浏览器中运行同一份代码重算。计划中与受阻的实验没有任何数值，页面显示“没有结果”与解锁条件。测试覆盖的实验只给出测试位置与命令，不引用某一次 CI 的结果。

**默认种子下的参考结果**（Node 22 本地计算，与构建结果相同）：

| 实验 | 结果 | 判定 |
| --- | --- | --- |
| SORT-01（n = 64，种子 2026） | 比较次数：随机 1,127 / 303 / 581；近乎有序 67 / 194 / 443；逆序 2,016 / 192 / 433；大量重复 611 / 279 / 562（插入 / 归并 / 快速） | 12 次输出均正确排序 · 通过；与 Showcase 基准表逐位相同（单元测试比对） |
| ROUTE-01（120 城，种子 7） | 距最优上界：均匀 15.29%、聚类 29.14%、环形 1.18%、网格 5.23% | 不短于 MST 下界、改进不变长、Or-opt 不差于 2-opt · 3/3 通过 |
| ROUTE-02（150 城，种子 11） | 三条路线各检查 11,025 个 2-opt 交换，可缩短的交换均为 0 | 通过 |
| NN-01（2-4-3-1 网络，种子 5） | 最大相对误差：tanh 3.69 × 10⁻⁸、ReLU 5.38 × 10⁻⁸、sigmoid 1.28 × 10⁻⁷ | 阈值 10⁻⁶ · 通过 |

判定标准与首个参考结果在同一次变更中写入，页面的判定标准处如实注明。单元测试另外在种子 1、42、99,999 上确认判定仍然成立。

**容差**：比较次数与交换个数逐位比对；路线长度允许 10⁻⁹ 的相对误差（吸收不同 JavaScript 引擎在高斯采样 `log`、`cos` 上可能的末位差异）；梯度误差本身是舍入噪声，比对时相对误差允许 5 × 10⁻⁷ 的差异，判定结论必须相同。

**与 Showcase 一致**：研究声明的主题与证据等级逐字等于 Showcase 项目页上的声明（单元测试强制），同一条声明不会出现两种状态。页面说明：复现结果不改变声明等级，等级只能随新版本的发布与审核改变。

**证据可核对**：开放的源码与测试证据都指向仓库中存在的文件；测试证据按测试标题引用，单元测试逐条确认标题确实出现在对应文件里；实验的代码入口逐个确认是该文件导出的符号；依赖版本与 `package.json` 一致（单元测试强制）。

**示例项目**：排序项目的“实验已验证”声明在页面上说明了按 Registry 契约它必须绑定证据资产，而示例项目还没有这个资产、平台也还不能分发数据类资产。体数据项目的证据全部标为“示例 · 无可打开的内容”，没有结果。

## 4. 权限与执行边界

- 页面全部公开、静态生成，不读取会话或用户数据。`/research` 不在 `platformPrefixes` 中，middleware 对它不做任何 Auth 处理（middleware 未改动）。
- 没有任何服务端运行入口。单元测试确认：渲染出的研究页面中没有带 `action` 或 `method="post"` 的表单，没有指向 `/api/` 的链接；`features/research` 与 `app/research` 的源码中没有 `fetch(`、`XMLHttpRequest`、`sendBeacon`、`EventSource`、`new Worker` 或 `/api/` 字符串。
- 本机复现在主线程运行（Node 中每个实验 2–30 ms），不发请求，结果只保存在组件状态（最多 20 条），离开页面即消失。
- 关联区块链接到已上线的两个公开 Demo，并注明它们独立于研究记录，不复现、也不改写任何实验。

## 6. 未验证事项与风险

- **浏览器视觉未覆盖**。浏览器自动化按仓库 AGENTS.md 处于停用状态，本轮未启动浏览器、未截图。布局、响应式断点、深色模式与动效只在服务端渲染层面检查，桌面与手机宽度仍需人工验收。重点：实验目录在 1024 px 上下的两种行布局；实验页侧栏在 1180 px 以下移到正文之后；Showcase 两个真实 Demo 的 Hero 现在最多有 5 个按钮，窄屏换行情况；站点导航增加到 6 项后在 900 px 附近的宽度。
- **客户端交互未在真实浏览器中运行**。筛选、query string 同步、`#claim-<id>` 直达与本机复现的逻辑由单元测试与服务端渲染覆盖，事件处理与 `history.replaceState` 未在浏览器中执行过。
- **跨引擎一致性未实测**。容差按 IEEE 754 与各引擎数学函数的差异设计，未在 Safari / Firefox 上实际比对。若出现不一致，页面会如实标出 ≠，不会掩盖。
- **低端设备耗时未测**。实验在主线程运行，Node 中最长约 30 ms；低端手机可能更慢，但不涉及网络。
- **构建提交号**：Vercel 构建会注入 `VERCEL_GIT_COMMIT_SHA`，页面显示短提交号并把代码链接固定到该提交；本地构建显示“未注入提交号”，代码链接指向 main。

L-1 … L-5 沿用 D2-A 交接；L-6 … L-9 为本次新增。实验记录在页面上引用这些编号。

| # | 需求 | 说明 |
| --- | --- | --- |
| L-1 | 证据资产读取 | 只读、绑定 Release 的证据资产地址与元数据（来源摘要、分发摘要、扫描版本、数据等级）；依赖 B3-A 之后的分发 |

| L-3 | 运行记录 | 绑定 `releaseId`、能力、种子、协议版本的运行：状态、结果、保留期限与可见性 |
| L-4 | 复现判定 | 由服务端按协议中的容差判定复现值与参考值是否一致；判定只追加事实，不修改已发布的 Release 或声明等级 |
| L-5 | L1 沙箱 | 第三方实验室代码的独立 origin、消息协议版本与权限边界 |
| L-6 | 研究目录只读 API | 研究项目、声明映射与实验记录的公开投影，形状见 `features/research/types.ts`；只返回 PUBLIC，UNLISTED 按 slug 可达；含 `showcaseSlug` 关联 |
| L-7 | 声明标识 | `researchClaimSchema` 目前没有 `id`；实验记录与证据需要稳定 id 才能引用具体声明。建议在 0.6.0 契约中加入，并要求同一 Release 内唯一 |
| L-8 | 受控运行环境 | 服务端、GPU 或 Python 运行环境：镜像摘要与依赖锁定、硬件规格随结果一起记录 |

## 8. 未来执行能力的身份、配额、隔离与审计需求

本轮不实现任何执行能力。若将来开放服务端或 GPU 复现，至少需要：

**身份**
- 公开访问者永远不能发起服务端运行，只能查看已经公开的运行记录与判定。
- 发起者必须是登录的项目成员，且具有专门的运行权限（不等同于 EDITOR），权限按项目与能力分别授予。
- 每次运行绑定发起人、项目、Release、协议版本、种子与参数；定时复现使用独立的服务身份，不借用个人身份。

**配额与预算**
- 默认预算为零；付费计算（GPU、第三方 API）需要 Owner 明确开启并设置上限。
- 按项目与按用户分别限制：并发数、单次最长时长、每日 GPU 秒数与费用；发起前显示预估，超出预算时硬停止并记录终态。
- 失败、超时与取消同样计入配额，避免以重试绕过限制。

**隔离**
- 每次运行使用一次性的沙箱（容器或虚拟机），资源上限覆盖 CPU、GPU、内存、磁盘与时长。
- 默认禁止出站网络；需要下载数据时只允许访问绑定该 Release 的签名资产地址。
- 不挂载任何平台密钥或用户凭据；输入只读。
- 输出先进入隔离区，经与 B3-A 相同的校验后才可见；任何交互界面走独立 origin（L-5）。
- 数据等级门禁：真实医学影像等受限数据不得进入运行。

**审计**
- 追加式、不可修改的审计日志：发起人、时间、Release、协议版本、种子与参数、镜像摘要、硬件规格、输入与输出摘要、费用、终态与错误码。
- 项目所有者可查看本项目的完整审计；公开页面只显示已公开的运行记录与复现判定，不显示发起人身份。
- 复现判定（L-4）作为事实追加，永不回写或覆盖已发布的声明等级。
